миграцию применяешь ты, по шагам ниже.

## Порядок выкладки

Миграцию применяй **до** слияния PR: сайт после деплоя сразу вызывает новые
функции. Если сделать наоборот, ничего не сломается (список пользователей
покажет «Что-то пошло не так», журнал ошибок и обращения просто не сохранятся),
но до миграции этими разделами пользоваться нельзя.

1. Проверь, что ты в нужном проекте и миграции ещё не применены:

   ```bash
   supabase migration list
   ```

   Последней применённой должна быть `20261010120000_year_recap`.

2. Примени миграцию (один файл, повторный прогон безопасен):

   ```bash
   supabase db push
   ```

3. Проверь права: открой `supabase/audit/previews_feedback_audit.sql` в SQL Editor
   и выполни по запросам. Ожидаемое написано рядом с каждым пунктом:
   - пункт 1: две строки `true`;
   - пункты 2 и 3: пусто (у `anon` и `authenticated` нет прямого доступа к таблицам);
   - пункт 4: `anon=true` только у `log_client_error`, у `scrub_client_text` и
     `client_errors_site_cap` оба `false`, у остальных `anon=false authenticated=true`;
   - пункт 5: у всех `search_path=""`.

4. Слей PR в `main`. Деплой соберёт сайт и страницы превью сам.

## Что проверить руками

### Превью ссылок (после слияния и деплоя)

Вокруг мессенджеров много кэша, поэтому проверяй на свежем адресе.

1. Убедись, что страница отдаётся и в ней есть теги (подставь свой релиз и трек):

   ```bash
   curl -s https://frnkness.ru/t/<releaseId>/<slug>/ | grep -E "og:(title|image|url)|twitter:card"
   curl -s https://frnkness.ru/r/<releaseId>/ | grep -E "og:(title|image)"
   curl -s https://frnkness.ru/ | grep -E "og:(title|image)"
   ```

   `og:image` должен быть абсолютным (`https://frnkness.ru/images/…`) и открываться в браузере.
2. На сайте нажми «Скопировать ссылку» на странице трека. В буфере должно быть
   `https://frnkness.ru/t/<релиз>/<слаг>/`, без `#`. То же на странице релиза: `/r/<релиз>/`.
3. **Telegram:** отправь эту ссылку себе в «Избранное». Должна появиться карточка с
   названием трека, описанием и обложкой релиза. Если карточка старая или пустая,
   Telegram закэшировал ответ: напиши ссылку боту [@WebpageBot](https://t.me/WebpageBot),
   он перечитает страницу.
4. **VK, WhatsApp и т. п.:** отправь ту же ссылку в личные сообщения. У VK кэш
   долгий, поэтому для повторной проверки добавь к адресу `?v=2`: страница статическая,
   параметр ей не мешает.
5. Открой ссылку в браузере: сразу должен открыться трек на `https://frnkness.ru/#/track/…`.
   Без входа откроется заставка, а после входа тот же трек.
6. Старые ссылки вида `https://frnkness.ru/#/track/…` работают как раньше.
7. Релиз, добавленный из админки: после его коммита в `main` и деплоя у него
   сразу есть `/r/<id>/` и `/t/<id>/<слаг>/`. Деплой «только контент» тоже запускает сборку.
8. У трека нет своей обложки, значит берётся обложка релиза. Нет и её, значит общая
   картинка `public/og-default.png` (её можно заменить своей, 1200×630).

Почему нет `<meta http-equiv="refresh">`: часть краулеров идёт по нему на
главную и берёт её общие теги вместо тегов трека. Перенаправление делает встроенный
скрипт, разрешённый в CSP страницы по хешу. Без JavaScript остаётся ссылка «Открыть».

### «Друзья»

1. Зайди в «Друзья» и нажми на поле «Найти по нику»: сразу виден список с аватаром,
   ником и кнопкой «Добавить в друзья» (или «Заявка отправлена» / «Уже друзья»).
2. Тебя самого и забаненных в списке нет. Ввод ника фильтрует список. При прокрутке
   вниз подгружаются следующие 30 человек (есть и кнопка «Показать ещё»).

### Подсказки

Зайди под свежим аккаунтом в «Избранное», «Мои плейлисты», «Лента», «Друзья» и на
свой профиль (блок топ-4): вместо пустоты текст и кнопка («Слушать Поток»,
«Найти друзей», «Выбрать треки»).

### Журнал ошибок

1. На сайте под своим аккаунтом открой консоль браузера и выполни
   `setTimeout(() => { throw new Error('проверка журнала') })`.
2. В админке: «Статистика» → «Ошибки». Должна появиться группа со счётчиком, временем
   и браузером. Повторное такое же сообщение в той же сессии в базу не попадает.
3. «Отметить решённой»: группа уходит во вкладку «Решённые». Если ошибка случится
   снова, она вернётся в «Нерешённые».
4. Записи старше 30 дней удаляются при открытии раздела.

Лимиты: не больше 20 записей в час с одного пользователя или браузера (случайный
ключ в `localStorage`) и не больше 500 в час на весь сайт. Всё сверх лимита молча
отбрасывается, сайт этого не замечает. В базу попадают сообщение, первые 8 строк стека,
страница без параметров адреса, браузер (семейство и версия), версия сборки и user_id,
если человек вошёл. Токены, пароли, почта и uuid вычищаются и в браузере, и ещё раз в базе.

### «Сообщить о проблеме»

1. Меню профиля → «Сообщить о проблеме»: поле до 1000 символов, после отправки
   «Спасибо, получили».
2. В админке: «Люди» → «Обращения»: ник, текст, страница, браузер, дата и статус
   «новое / решено». Число новых показано значком у пункта в боковой панели.
3. Лимит: 5 обращений в сутки на пользователя, шестое получает отказ с понятным текстом.

## Аудит прав на новые таблицы и функции

- `client_errors` и `feedback_reports`: RLS включён, политик нет, права у `anon` и
  `authenticated` отозваны, полный доступ только у `service_role`. Читают и пишут
  только функции ниже.
- Открыта анониму одна функция: `log_client_error`. Она не бросает исключений, ограничена
  лимитами (пользователь или браузер, плюс общий потолок) и вычищает данные.
- Только вошедшим (`authenticated`, внутри `require_active_user`): `list_discoverable_users`,
  `submit_feedback`. Забаненный и удалённый получают «Нужно войти».
- Только admin и owner (проверка `is_admin()` внутри): `admin_errors_list`,
  `admin_errors_resolve`, `admin_feedback_list`, `admin_feedback_set`,
  `admin_feedback_new_count`.
- Внутренние `scrub_client_text` и `client_errors_site_cap` не доступны никому из сайта.
- Все функции `security definer` с `search_path = ''`.
- `list_discoverable_users` отдаёт только id (нужен для заявки), ник, аватар и отношение к
  вызывающему. Без забаненных, удалённых и самого вызывающего.
- Все тексты (ошибки, обращения, ники) выводятся интерполяцией Vue, то есть с экранированием.
  В `og:`-страницах значения экранируются, а скрипт перенаправления построен из JSON-литерала.

Проверяют это SQL-тесты `supabase/tests/previewsFeedback.test.ts` (права, лимиты, вычистка,
группировка, удаление старых записей) и сам аудит-скрипт.

## Откат

Новые объекты ничего существующего не меняют. Если миграцию нужно убрать:

```sql
drop function if exists public.list_discoverable_users(text, text, integer);
drop function if exists public.log_client_error(text, text, text, text, text, text);
drop function if exists public.admin_errors_list(boolean);
drop function if exists public.admin_errors_resolve(text, boolean);
drop function if exists public.submit_feedback(text, text, text, text);
drop function if exists public.admin_feedback_list(text);
drop function if exists public.admin_feedback_set(bigint, text);
drop function if exists public.admin_feedback_new_count();
drop function if exists public.scrub_client_text(text, integer);
drop function if exists public.client_errors_site_cap();
drop table if exists public.client_errors;
drop table if exists public.feedback_reports;
```

После отката сайт продолжит работать: журнал ошибок молчит, а «Друзья» и обращения
покажут сообщение об ошибке.
