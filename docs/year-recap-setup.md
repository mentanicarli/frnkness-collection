# Запуск «Итогов года»: пошаговая инструкция

Что появится:

- **Админка → «Статистика» → «Итоги года»:** выбор года, общие цифры по всем,
  просмотр итогов любого пользователя (те же карточки, что увидит он сам) и
  публикация: «Показать всем», «Показать выбранным», «Скрыть у всех»,
  «Скрыть выбранным». Видно, кому сейчас открыто.
- **Сайт:** пока итоги не открыты, у пользователя нет ни плашки, ни ссылок, а
  адрес `#/recap/<год>` уводит на главную. Когда открыты — плашка «Твои итоги
  <год> готовы» при входе («Смотреть» / «Закрыть»), ссылка «Итоги <год>» в
  меню профиля, в «Мой профиль» и в настройках. Просмотр — полноэкранные
  карточки (свайп, стрелки, клик), последняя — сводка и «Сохранить картинку»
  (PNG 1080×1920 для сторис).

**Порядок:** сначала база, потом мерж. Сайт без миграции просто не покажет
итоги (запрос состояния вернёт ошибку и сайт сочтёт итоги закрытыми), а
админка раздела «Итоги года» без миграции покажет ошибку — поэтому база идёт
первой.

**Функции Supabase не менялись** — `functions deploy` не нужен, секретов нет.
Миграция одна.

## Что считается

- Период: с 1 января выбранного года (или с даты регистрации, если она
  позже) до 31 декабря, время московское.
- Год ещё идёт — итоги пересчитываются при каждом просмотре. Год закончился —
  итоги один раз сохраняются в `recap_snapshots` и больше не меняются.
- Минуты (по сессиям прослушивания), число прослушиваний, топ-5 треков,
  любимый релиз, первый трек года, самый активный день, любимое время суток
  (утро 5–11, день 11–17, вечер 17–23, ночь 23–5), число комнат и топ-3
  собеседников (по времени, когда были в комнате одновременно), сколько
  треков добавлено в избранное.
- Мало данных (меньше 10 прослушиваний): показываются только карточки, где
  данные есть, плюс заметка «Ты только начинаешь»; «любимый релиз», «самый
  активный день» и время суток не показываются. Данных нет совсем — одна
  дружелюбная карточка и никакой картинки.
- Прослушивания без аккаунта (до регистрации и гостевые) в итоги не входят.


В списке должна быть **одна** миграция: `20261010120000_year_recap.sql`. Если
есть что-то ещё — остановись и пришли мне вывод. Если всё так:


Миграция создаёт три закрытые таблицы (`recap_settings`, `recap_grants`,

## Шаг 6. Проверка на своём компьютере

```bash
npm run dev
```

Нужны два окна: админка (`/admin.html`) под админом или владельцем и сайт под
обычным аккаунтом (второе — в инкогнито).

**Пока закрыто**

1. Сайт под обычным аккаунтом: плашки нет, в меню профиля, в «Мой профиль» и
   в настройках нет «Итоги». Открой вручную `#/recap/2026` (текущий год) —
   вернёт на главную.
2. Админка → Статистика → **Итоги года**: выбери год, видишь общие цифры и
   «Закрыто для всех». У любого пользователя нажми «Посмотреть» — карточки
   открываются, несмотря на закрытый доступ.

**Показать выбранным**

3. Найди обычный аккаунт по нику, поставь галочку, «Показать выбранным».
   В списке «Кому открыты» он появился, в строке пользователя — «открыто».
4. Сайт под этим аккаунтом: **обновить страницу** → плашка «Твои итоги <год>
   готовы». «Закрыть» — после перезагрузки сама больше не появляется (это
   запоминается на этом устройстве). Ссылка «Итоги <год>» в меню профиля
   остаётся.
5. Другой обычный аккаунт ничего не видит; его собственный адрес
   `#/recap/<год>` уводит на главную.

**Просмотр**

6. «Смотреть»: карточки листаются стрелками клавиатуры, кнопками ‹ ›,
   нажатием (левая треть экрана — назад, остальное — вперёд) и свайпом;
   прогресс сверху; × или Esc закрывают. Названия длинных треков не вылезают
   за край, ник и тексты — обычным текстом (вставь в ник `<b>`/`&amp;` через
   админку — должно показаться как есть).
7. Карточки без данных (нет комнат, нет избранного) не показываются.

**Картинка (самое важное — проверь руками)**

8. **Chrome на компьютере:** последняя карточка → «Сохранить картинку» →
   скачивается `frnkness-recap-<год>.png`. Открой: 1080×1920, виден ник
   (и аватар, если он загружен), минуты, три трека с обложками, любимый
   релиз, внизу `frnkness.ru`. Шрифты — Unbounded/Golos (не системные).
9. **Android (Chrome):** то же — файл появляется в «Загрузках» / «Галерее».
10. **iPhone (Safari):** «Сохранить картинку» открывает окно «Поделиться» →
    «Сохранить изображение» (попадает в «Фото»). Если окно не открылось,
    картинка откроется в новой вкладке — нажми и удерживай, «Сохранить в
    Фото». Закрыл окно «Поделиться» — это не ошибка.
11. Аватар по ссылке Supabase Storage не загрузился (отключи сеть на время
    или поставь аватар-инициалы) — картинка всё равно рисуется, просто без него.

**Показать всем / скрыть**

12. «Показать всем» (подтверждение) → статус «Открыто всем», у всех
    появляется плашка. Зарегистрируй новый аккаунт — он тоже видит итоги.
13. «Скрыть выбранным» при режиме «всем» — у этого человека итоги пропадают
    (в списке пометка «скрыто»), у остальных остаются. «Показать выбранным»
    вернёт. «Скрыть у всех» убирает всё.

## Приватность и права

- Таблицы `recap_*` закрыты полностью: у `anon` и `authenticated` нет прав, в
  RLS нет политик. Читают и пишут только функции (`security definer`,
  `search_path=""`).
- `year_recap(год, пользователь)`: обычный пользователь получает только свои
  итоги и только когда они ему открыты. Чужой `user_id`, закрытые итоги, бан,
  будущий год — один и тот же ответ «Недоступно» (код 42501): по ответу не
  понять, есть ли у кого-то итоги. Админ и владелец видят итоги любого
  пользователя, даже закрытые.
- Админские функции (`admin_recap_*`) — только `is_admin()` (админ и владелец),
  роль читается из `auth.users`, а не из токена.
- «Показать всем» хранится как режим года, а не как список людей, поэтому
  распространяется и на тех, кто зарегистрируется позже. Личные исключения
  («скрыто» при режиме «всем») хранятся отдельно в `recap_grants`.
- Все тексты выводятся шаблонами Vue (экранирование), в картинку — только
  через `fillText`.

## Что в итогах считается неточно

- «Минуты» — по сессиям прослушивания (`listen_sessions`, реально
  прослушанное без перемоток). Сессии пишутся с момента запуска этой таблицы
  (этап «Дослушивают или пропускают»): за более ранние месяцы минут не будет,
  а прослушивания (`play_events`) — будут.
- Время суток и «первый трек» считаются по `play_events` (момент начала трека).
- Собеседники в комнатах — по журналу комнат (`room_visits`), он ведётся с
  этапа «Топ-4, лента, реакции»: что было раньше — не попадёт.
